HomeCare 기술 명세서v0.1 · 개발팀용

퇴원 환자가 홈펌프(특수항암기계)로 항암제를 44시간 자가 투여하는 동안, 하루 3번 점검 알람 + 3가지 체크 + 이상 상황 대처 + 의료진 공유용 기록을 제공하는 모바일 웹앱입니다.

사용 기간
2박 3일 (44h ±7h)
플랫폼
Web App (iOS / Android)
데이터 저장
환자 단말 로컬 (서버 X)
의료진 접근
PDF 내보내기로만
설계 원칙 서버 의존성 없이 환자 단말에서 완결되도록 설계합니다. 어드민/관리자 콘솔은 v1 범위에서 제외하며, 의료진은 외래 방문 시 환자가 보여주는 PDF로만 기록을 확인합니다.

한 페이지 흐름 요약

  1. 의료진 입력 — 수동 입력 → 잠금
  2. 환자 인수 — 단말 전달, 짧은 온보딩
  3. 대시보드 — 진행률, 다음 알람 카운트다운
  4. 점검 플로우 — 눈금 / 잠금장치 / 온도센서
  5. 이상 상황 — 5가지 시나리오 + 직통 전화
  6. 기록 — 타임라인 + 눈금 추이 차트
  7. PDF — 외래 진료용 리포트
  8. 완료 — 눈금 0 → 병원 복귀 안내

데이터 모델

// types/domain.ts
export interface Patient {
  name:      string;
  mrn:       string;        // 등록번호
  birth:     string;        // YYYY-MM-DD
  regimen:   string;        // FOLFOX / FOLFIRI / ...
  cycle:     string;        // "4 / 12"
  ward:      string;
  doctor:    string;
  nurse:     string;
  wardPhone: string;
  erPhone:   string;
}

export interface Schedule {
  startAt:     ISODateTime;  // 의료진이 병동에서 입력
  totalHours:  44;
  alarms: { morning: HHMM; noon: HHMM; evening: HHMM };
}

export interface Check {
  id:        string;
  at:        ISODateTime;
  slot:      'morning' | 'noon' | 'evening' | 'adhoc';
  scaleMl:   number;          // 풍선 잔량 ml
  locks:     [boolean, boolean]; // [포트쪽, 펌프쪽]
  tempOk:    boolean;
  ok:        boolean;
  note?:    string;
  photoBlob?: Blob;
}

export interface AlertEvent {
  id:   string;
  at:   ISODateTime;
  type: 'no_change' | 'leak' | 'locked' | 'fever' | 'pain';
  acknowledged: boolean;
  calledWard?:    boolean;
}

export interface Settings {
  staffLocked:   boolean;
  staffPinHash?: string;
  pushEndpoint?: string;
  locale:        'ko';
}

저장 · 동기화 전략

저장 위치

  • IndexedDB는 환자 단말의 단일 진실 공급원(SSOT)입니다.
  • 환자 정보는 병동에서 의료진이 수동 입력합니다 — EMR 연동 없음.
  • 서버에는 환자 데이터를 보내지 않습니다 (개인정보 처리 동의 부담 최소화).

Persist 미들웨어

// stores/persist.ts
import { create } from 'zustand';
import { persist, createJSONStorage } from 'zustand/middleware';
import * as idb from 'idb-keyval';

const idbStorage = {
  getItem:    async (k: string) => (await idb.get(k)) ?? null,
  setItem:    async (k: string, v: string) => idb.set(k, v),
  removeItem: async (k: string) => idb.del(k),
};

export const usePatientStore = create<PatientState>()(
  persist(
    (set) => ({
      patient: null,
      setPatient: (p) => set({ patient: p }),
    }),
    { name: 'homecare-patient', storage: createJSONStorage(() => idbStorage) },
  ),
);

EMR 연동 — 속편 (v2)

v1은 병동에서 의료진이 수동으로 환자 정보를 입력합니다 — EMR 연동 없음. v2에서 QR 스캔 또는 server-to-server 연동을 검토합니다. 

// /setup/patient — 수동 입력 저장
function savePatient(form: PatientForm) {
  const data = PatientSchema.parse(form);   // zod 검증
  usePatientStore.getState().setPatient(data);
}
수동 입력 주의 환자 이름·등록번호·처방을 의료진이 직접 입력하므로, 입력 실수 방지용 검증(zod) 과 확인 화면을 튼튼히 두세요.

내보내기 (Export)

  • PDF 저장 — 외래 진료 시 의료진에게 제출. @react-pdf/renderer로 생성 → 단말에 다운로드.
  • v2 공유하기 — navigator.share()는 고도화로 이연. v1은 PDF 다운로드만.

잠금 메커니즘

settings.staffLocked = true가 되면 환자 UI로 라우트됩니다. 설정 화면에서 의료진이 다시 입력 모드로 돌아가려면 4자리 PIN (병동 공통, argon2id 해시) 필요. 

// services/lock.ts
export async function unlockStaff(pin: string): Promise<boolean> {
  const ok = await argon2.verify(settings.staffPinHash!, pin);
  if (ok) useSettingsStore.getState().set({ staffLocked: false });
  return ok;
}
UI 검은 헤더 + 노랑 "RN" 배지로 환자 모드와 시각적으로 명확히 구분. 환자가 실수로 들어와도 즉시 알아챌 수 있어야 합니다.

// hooks/useTick.ts — 분 단위 강제 리렌더
export function useTick(intervalMs = 60_000) {
  const [, set] = useState(0);
  useEffect(() => {
    const id = setInterval(() => set((n) => n + 1), intervalMs);
    return () => clearInterval(id);
  }, [intervalMs]);
}

// services/checks.ts
export async function submitCheck(draft: CheckDraft) {
  const check: Check = {
    id: crypto.randomUUID(),
    at: new Date().toISOString(),
    slot: resolveSlot(new Date(), schedule.alarms),
    ...draft,
    ok: isAllOk(draft),
  };
  await useChecksStore.getState().add(check);
  notifyService.cancelMissedReminder();
}

눈금 추이 차트 데이터

  • X축: (check.at − schedule.startAt) / 1h → 0..44 시간
  • Y축: check.scaleMl → 0..130 ml
  • 예상선: (0, 120) → (44, 0) 선형 보간
  • "현재" 수직선: 점선, 노랑색
function feedbackForChecks(checks: Check[]) {
  const okStreak = currentOkStreak(checks);
  const avgRate  = avgMlPerHour(checks);
  if (avgRate < 1.5) return { tone: 'warn',  msg: '줄어드는 속도가 느려요' };
  if (okStreak >= 3)  return { tone: 'safe',  msg: '예상 속도대로 잘 진행되고 있어요' };
  return                  { tone: 'brand', msg: '기록을 이어가주세요' };
}

PDF 구성

  1. 헤더 — 환자 인적사항, 요법, 작성일
  2. 요약 — 총 점검 횟수, 이상 없음 횟수, 이상 보고 횟수
  3. 차트 — SVG → PNG (html-to-image) → PDF embed
  4. 점검 테이블 — 시간 / 눈금 / 잠금 / 센서 / 메모
  5. 알림 이벤트 — 시각, 종류, 조치
  6. 면책 문구 — "환자 자가 측정 기록"
// services/pdf.ts — v1: PDF 다운로드만
export async function generateReport() {
  const [patient, schedule, checks, alerts] = await Promise.all([
    load('patient'),  load('schedule'),
    loadAll('checks'), loadAll('alerts'),
  ]);
  const chartPng = await renderChartToPng(checks, schedule);
  const blob = await pdf(<Report {...{ patient, schedule, checks, alerts, chartPng }} />).toBlob();
  downloadBlob(blob, filename(patient));   // e.g. HomeCare_김민서_20389471_20260522.pdf
}

알람 · 푸시

요구사항

  • 하루 3번, 환자가 설정한 시각에 푸시 알림
  • 알람 후 30분 내 점검이 없으면 재알림 (1회)
  • iOS 16.4+ Safari, Android Chrome 모두 지원

구현

  1. 앱이 POST /api/push/subscribe로 endpoint + keys 등록
  2. 서버는 환자별 알람 스케줄(시각 + 시간대)을 cron으로 보관
  3. 매 시각 도래 시 web-push로 발송
  4. SW의 push 이벤트 핸들러가 노티 표시 → 클릭 시 /check/0으로 이동
// public/sw.js
self.addEventListener('push', (e) => {
  const { title, body, url } = e.data.json();
  e.waitUntil(self.registration.showNotification(title, {
    body, icon: '/icons/icon-192.png', badge: '/icons/badge.png',
    data: { url }, tag: 'homecare-check', renotify: true,
  }));
});

self.addEventListener('notificationclick', (e) => {
  e.notification.close();
  e.waitUntil(clients.openWindow(e.notification.data.url ?? '/check/0'));
});
iOS 주의 iOS는 PWA로 홈 화면에 추가된 경우에만 Web Push가 작동합니다. 환자 인수 화면에서 설치를 강하게 권유해야 합니다.

오프라인 / PWA

  • Service Worker가 앱 셸을 cache-first로 캐시 → 인터넷 없어도 점검 가능
  • 모든 데이터가 IndexedDB에 있으므로 동기화 충돌 우려 없음
  • 웹 매니페스트로 홈 화면 설치 지원: display: 'standalone', orientation: 'portrait'
  • 유저 에이전트가 PWA 모드인지 감지해서 install 안내를 조건부 노출

테스트 · QA

  1. resolveSlot() — 현재 시각으로부터 morning/noon/evening 매핑

Open Questions

  1. 의료진 PIN — 병동별 / 환자별 / 단말 공통? 운영 시나리오에 따라 결정.
  2. 알람 재시도 — 30분 후 1회로 충분? 야간 알람 정책은?
  3. 사진 첨부 — 이상 보고 시 사진 첨부 옵션 (데이터 모델에 placeholder 있음)
  4. 다국어 — v1 한국어 only. 외국인 환자 비율에 따라 영어 추가 검토.
  5. EMR 연동 — v1은 수동 입력. v2에서 QR 스캔 또는 server-to-server 결정.
